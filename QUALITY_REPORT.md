Дата сборки: **6 августа 2026 года**  
Проект: **Amir’s English Space**  
Режим начальных материалов: **empty**

## Принятые входные параметры

- ученик: Амир / Amir;
- `STUDENT_ID`: `amir`;
- уровень ученика: A1;
- учебник: English File, Pre-Intermediate A2;
- язык пользовательского интерфейса: `en`;
- русская поддержка: 5%;
- часовой пояс преподавателя: `Europe/Riga`;
- базовый URL сайта: пусто;
- Supabase URL и public anon key: взяты из переданного задания;
- учебные материалы: не переданы.

Поля языка и процента русской поддержки во входном блоке были записаны как шаблонные/повреждённые значения. Применены явно заданные в спецификации значения по умолчанию: `en` и 5%.

## Что создано

Создан самостоятельный статический движок на HTML5, CSS3 и vanilla JavaScript:

- главная страница;
- список домашних работ и универсальная страница урока;
- разделы грамматики и словаря;
- пустые состояния для нового курса;
- автоматическое обнаружение `lesson-N.json`;
- универсальный renderer учебных блоков и оцениваемых элементов;
- локальное сохранение, persistent sync queue и синхронизация с Supabase;
- одноразовая финальная отправка домашней работы с UUID и блокировкой после подтверждения базы;
- атомарное применение итогов словарного теста через PostgreSQL RPC;
- Web Speech API для произношения;
- полная схема из семи таблиц, RLS, ограничения и триггеры;
- Edge Function для отчётов и публикаций;
- два GitHub Actions workflow;
- безопасная диагностическая страница;
- шаблоны урока, словаря и грамматики;
- документация по настройке и публикации.

## Материалы, созданные из приложенных источников

Из источников создана только архитектура, дизайн-система и функциональная модель сайта. Персональные учебные тексты, упражнения, ответы, изображения, аудио и прогресс исходного ученика не переносились.

## Материалы, пропущенные из-за недостатка данных

В режиме `empty` намеренно не созданы:

- опубликованные `lesson-N.json`;
- словарные темы и слова;
- грамматические темы;
- MP3-файлы;
- учебные изображения;
- тестовый прогресс и ответы;
- фиктивный Telegram chat ID.

Поэтому начальные показатели сайта равны нулю, а разделы показывают полноценные пустые состояния.

## Проверки безопасности и целостности

Подтверждено статически:

- в клиенте нет service-role key, bot token, webhook secret или Telegram chat ID;
- public anon key находится только в `config.js`, как предусмотрено браузерной архитектурой;
- Edge Function не доверяет баллам и ответам из тела запроса;
- URL Telegram-кнопки принимается только как HTTPS URL того же origin, что `SITE_BASE_URL`;
- отчёты и публикации дедуплицируются уникальными ограничениями;
- записи `failed` и зависшие `pending` допускают безопасную повторную доставку;
- финальная домашняя работа блокируется локально только после подтверждённой записи Supabase;
- финальная запись в облаке имеет приоритет над локальным черновиком;
- clearing `localStorage` не отменяет облачную блокировку;
- роль `anon` не имеет DELETE для `homework_progress` и не имеет доступа к серверным таблицам;
- данные учебного курса и прогресс исходного ученика отсутствуют;
- служебная история Git и мусор macOS отсутствуют.

## Что требует владельца внешних сервисов

Локально не заявляются как выполненные:

- применение `supabase/schema.sql` к удалённому проекту;
- успешное выполнение `supabase/verify.sql` в реальной базе;
- проверка RLS через реальный Supabase API после применения схемы;
- добавление реального получателя в `telegram_recipients`;
- развёртывание Edge Function;
- реальная доставка Telegram-сообщения;
- повторный вызов против реального Telegram API;
- выполнение GitHub Actions в репозитории владельца;
- полный ручной сценарий отправки учебного урока, поскольку опубликованных материалов в режиме `empty` нет.

Для этих проверок нужны доступ владельца Supabase, GitHub secrets, Telegram bot token, chat ID и хотя бы один подтверждённый учебный материал.
